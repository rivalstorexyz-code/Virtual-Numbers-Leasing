# رمزون SMS — المشروع الكامل بعد تحديث التنبيه

## ما الذي تغيّر؟
- إضافة دليل واضح أعلى نافذة استلام SMS: «الرقم المطلوب هنا — اضغط لنسخه».
- عند استلام أول كود فعلي من خادم الطلب يتغير الدليل تلقائيًا إلى «انسخ الكود من هنا»، وينسخ أحدث كود عند الضغط.
- عند استقبال عدة أكواد، تبقى كلها ظاهرة، ويشير الدليل إلى أحدث كود.
- استمرار تعديلات لوحة Render وحاسبة رسوم سلة من نسخة المراجعة السابقة؛ لم تُغيّر متغيرات البيئة أو بيانات Neon.

## نشر GitHub بطريقة آمنة
1. احتفظ بنسخة احتياطية من قاعدة Neon ومن ملفات مستودع GitHub قبل أي تغيير.
2. فك ضغط ملف ZIP **على جهازك**. لا ترفع ZIP نفسه إلى المستودع.
3. تأكد أن مجلدات app وadmin وtemplates والملف vercel.json في جذر المستودع مباشرة، لا ضمن مجلد إضافي.
4. افتح المستودع المربوط بـ Vercel وRender في GitHub. استخدم فرعًا جديدًا للتجربة (مثل ramzon-update) وارفع الملفات المستخرجة مع الحفاظ على مساراتها.
5. عند استبدال الملفات الموجودة في GitHub، يفضّل GitHub Desktop أو git على الكمبيوتر لضمان تحديث الملفات وحذف القديم عند الحاجة؛ واجهة رفع ملفات GitHub على الجوال لا تضمن دمج مجلدات المشروع بشكل آمن.
6. اختبر النشر التجريبي لـ Vercel وRender، ومسارات /buy والطلبات و/health، وتسجيل الدخول إلى الإدارة، ثم ادمج الفرع مع main بعد نجاح التجربة.
7. في Render، متغير ADMIN_SECRET مطلوب لحماية لوحة الإدارة. لا تضعه داخل الملفات ولا تشاركه في الدردشة؛ احتفظ بمتغيرات DATABASE_URL وSIM5_API_KEY في إعدادات الخدمات.
8. لا تعدّل Neon يدويًا أو تشغّل تغييرات قواعد بيانات قبل أخذ نسخة احتياطية وفهم مخطط الترحيل.

## ملاحظات
- هذه نسخة مراجعة لم تُختبَر على حساب المورد أو Neon أو سلة الفعلية؛ لا ترفع مباشرة للإنتاج قبل اختبار التدفق.
- إعداد سعر الصرف في لوحة الإدارة يُحفظ في المتصفح وفق النسخة الحالية، وليس إعدادًا مشتركًا محفوظًا في الخادم.
- نظام «مباع» هو تصنيف الأعمال الذي اختاره صاحب المشروع (مستخدم أو محاولة) وليس تأكيد عملية مالية من سلة.
